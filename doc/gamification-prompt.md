# پرامپت آماده برای Claude Code — سیستم گیمیفیکیشن «آدمکِ روز»

> **نحوه استفاده:** روی برنچ `gamification` هستی. کل متن پایین (از خط «### START PROMPT» تا آخر فایل) را کپی کن و در Claude Code پیست کن. اگر خواستی کوتاه‌تر شود، فقط بخش «فاز ۰ تا ۴» را بده — بقیه نقشه راه است.

### START PROMPT

تو روی ریپازیتوری «پنهان» (hesabkon) کار می‌کنی: یک Personal OS فارسی با Next.js + Prisma + Capacitor.
روی برنچ `gamification` هستیم. هدف این تسک ساختن یک **سیستم گیمیفیکیشن مبتنی بر یک آدمک (Companion)** است که کاربر را مشتاق کند داده وارد کند.

قبل از نوشتن کد، این فایل‌ها را بخوان تا سبک و قواعد موجود را بفهمی:

- `src/lib/dayBattery.ts` و `src/components/DayBattery.tsx` — منطق تایم‌لاین روز و قانون «هیچ‌وقت قضاوت نکن»
- `src/lib/phrasing.ts`، `src/lib/narrative.ts` — قانون **درد → مسیر → افتخار** (pain → path → pride)
- `src/lib/milestones.ts`، `src/lib/identity.ts`، `src/lib/insights.ts`، `src/lib/dailyMoment.ts` — الگوی «تابع خالص + تست + داده‌ساز جدا»
- `src/app/(app)/page.tsx` — صفحه Home که **اسکرول ندارد** و همه‌چیز باید above the fold جا شود
- `src/lib/localDispatcher.ts` و `src/local/reportEngine.ts` — لایه داده آفلاین اندروید
- `src/lib/hooks.ts` (`useHabits`) — منبع دقیقه‌های عادت امروز

## ۱. هدف محصولی

کاربر باید **قبل از ثبت داده هم دلیلی داشته باشد اپ را باز کند**، و بعد از هر ثبت یک پاداش فوری و دیدنی بگیرد.
آدمک این کار را می‌کند: یک شخصیت ساده که حال‌وروزش بازتاب روزِ کاربر است.

قاعده مرکزی که هرگز نقض نمی‌شود:

> **آدمک به «روز» واکنش نشان می‌دهد، نه به «آدم».**
> هرگز کاربر را شرمنده نمی‌کند، هرگز از او ناامید نمی‌شود، و هرگز بدون یک راهِ خروجِ قابل‌کلیک، حالت منفی نشان نمی‌دهد.

## ۲. قوانین غیرقابل‌مذاکره

**محصولی:**

1. حالت منفی آدمک همیشه باید کنارش یک **اکشن قابل‌کلیک** داشته باشد (باز شدن `CaptureFormModal`) — همان قانون pain→path→pride.
2. صبح زود **هرگز** حالت منفی نمی‌دهد. ۰ ساعت کار در ساعت ۷:۳۰ صبح طبیعی است، نه شکست.
3. دسته `WASTE` هرگز قرمز نمی‌شود و آدمک بابتش عصبانی/غمگین نمی‌شود. ثبت صادقانه اتلاف باید **همان‌قدر** پاداش بگیرد که ثبت کار مفید — وگرنه کاربر اتلاف را ثبت نمی‌کند و هسته محصول (هزینه پنهان) می‌میرد.
4. هیچ مکانیکی نباید به **تعداد ثبت** پاداش بدهد (تولید داده زباله). پاداش به **پوشش زمان** و **رسیدن به هدف** است.
5. لحن بزرگسال و آرام. بدون شکلک‌بارانی و بدون لحن کودکانه.

**فنی:**

6. منطق در یک **ماژول خالص و تست‌پذیر** باشد: `src/lib/companion.ts` — بدون دسترسی DB، بدون `Date.now()` داخلی (زمان تزریق می‌شود). دقیقاً مثل `dayBattery.ts`.
7. **هیچ endpoint جدیدی نساز.** حالت آدمک کاملاً از داده‌های موجود در کلاینت محاسبه می‌شود: پاسخ `GET /api/day-battery` + `GET /api/settings` + دقیقه‌های عادت امروز از `useHabits`. این یعنی صفر کار اضافه در `localDispatcher.ts` و صفر ریسک واگرایی وب/اندروید.
8. پول = `Int` تومان، زمان = `Int` دقیقه. هیچ float.
9. RTL و فارسی در همه‌جای UI. تاریخ‌ها از `src/lib/jalali.ts`.
10. تست با Vitest کنار ماژول: `src/lib/companion.test.ts`.
11. فیلدهای جدید Settings باید `db push`-safe باشند (نوع ساده + مقدار پیش‌فرض literal) — توضیح داخل `prisma/schema.prisma` را بخوان و رعایت کن. هر فیلد جدید باید در **هر سه جا** اضافه شود: `prisma/schema.prisma`، `prisma/schema.postgresql.prisma`، `src/local/generatedSchema.ts`.

## فاز ۱ — موتور خلق‌وخو: `src/lib/companion.ts`

### ورودی

```ts
export interface CompanionInput {
  now: Date;
  wakeTime: Date;              // امروز، از settings.wakeHour
  sleepTime: Date;             // امروز، از settings.sleepHour
  productiveMinutes: number;   // مجموع سگمنت‌های PRODUCTIVE از /api/day-battery
  habitMinutes: number;        // دقیقه‌های عادت‌های امروز (DayBattery عمداً اینها را ندارد، ولی برای مود می‌شمارند)
  wasteMinutes: number;
  neutralMinutes: number;
  unloggedMinutes: number;     // از /api/day-battery
  targetMinutes: number;       // settings.dailyProductiveTargetMin
  loggedEntriesToday: number;  // فقط برای تشخیص «هنوز هیچی ثبت نشده»
}
```

### فرمول

```
elapsed        = clamp(now, wakeTime, sleepTime) - wakeTime          // دقیقه
capacity       = sleepTime - wakeTime
dayProgress    = capacity > 0 ? elapsed / capacity : 0
achieved       = productiveMinutes + habitMinutes
expectedByNow  = targetMinutes * dayProgress
pace           = expectedByNow <= 0 ? 1 : achieved / expectedByNow    // «چقدر از انتظارِ همین لحظه جلو/عقبی»
completion     = targetMinutes <= 0 ? 0 : achieved / targetMinutes    // درصد هدف روز
blindness      = elapsed <= 0 ? 0 : unloggedMinutes / elapsed
```

**نکته کلیدی:** مود بر اساس `pace` است نه `achieved` خام. به همین دلیل ساعت ۹ صبح با ۰ ساعت کار، آدمک خنثی است نه ناراحت — و این تنها چیزی است که این مکانیک را از یک ابزار احساس‌گناه جدا می‌کند.

### حالت‌ها (به ترتیب اولویت ارزیابی)

| # | key | شرط | چهره | لحن |
|---|-----|------|------|------|
| ۱ | `ASLEEP` | `now < wakeTime` یا `now > sleepTime + 60min` | خواب، چشم‌ها خط بسته | ساکت |
| ۲ | `FRESH` | `elapsed < 90` (گریسِ صبح) | آرام، چشم‌های باز، لبخند خیلی کم | «روز تازه‌ست» |
| ۳ | `BLINDFOLDED` | `elapsed >= 180 && blindness > 0.6` | چشم‌بسته با دست جلوی چشم | «نمی‌دونم امروز چه خبر بوده» |
| ۴ | `CELEBRATING` | `completion >= 1.5` یا رسیدن به هدف در روزِ تمام‌شده | چشم بسته از خنده + کانفتی | جشن کوتاه |
| ۵ | `HAPPY` | `completion >= 1` | لبخند پهن، چشم‌های برق‌دار | افتخار |
| ۶ | `CONTENT` | `pace >= 0.8` | لبخند ملایم | تأیید |
| ۷ | `NEUTRAL` | `pace >= 0.4` | خنثی | واقعیت خشک |
| ۸ | `SLEEPY` | `pace < 0.4` | پلک‌های نیمه، خمیازه | «هنوز وقت هست» + دکمه ثبت |

`SLEEPY` پایین‌ترین حالت است — **کسل، نه ناراحت، نه قضاوت‌گر**. عمداً هیچ حالت «غمگین/ناامید» وجود ندارد.

### خروجی

```ts
export type CompanionMood = "ASLEEP" | "FRESH" | "BLINDFOLDED" | "CELEBRATING" | "HAPPY" | "CONTENT" | "NEUTRAL" | "SLEEPY";

export interface CompanionState {
  mood: CompanionMood;
  completion: number;      // 0..1+ برای حلقه پیشرفت
  pace: number;
  achievedMinutes: number;
  targetMinutes: number;
  remainingMinutes: number;   // تا هدف
  message: string;            // متن فارسی حباب گفتار
  action: { label: string; kind: "CAPTURE" | "LOG_GAP" | "NONE" };
}
```

متن‌ها را در `src/lib/phrasing.ts` بگذار (کنار بقیه متن‌های محصول)، نه inline در کامپوننت. برای هر مود ۳ تا ۴ جمله بنویس و با seed روزانه (الگوی `dailyMomentSeed`) بین‌شان بچرخ تا تکراری نشود.

نمونه‌های تأییدشده:

- `SLEEPY` → «تا الان ۴۰ دقیقه ثبت شده. هنوز ۷ ساعت از روزت مونده.» + دکمه «ثبت کار»
- `BLINDFOLDED` → «۵ ساعت از امروز رو نمی‌بینم. یکی‌شون رو بهم بگو.» + دکمه «پر کردن بازه»
- `CONTENT` → «روی خط هستی. ۲ ساعت تا هدف.»
- `HAPPY` → «۶ ساعت کار مفید. هدف امروز رسید.»
- `CELEBRATING` → «۹ ساعت. امروز از خودت جلو زدی.»

**هر عدد در این جملات باید واقعی و از داده باشد. هیچ جمله انگیزشی توخالی و بدون عدد ننویس** (همان قانونی که `insights.ts` رعایت می‌کند).

## فاز ۲ — کامپوننت: `src/components/companion/Companion.tsx`

- **SVG درون‌خطی**، بدون فایل تصویر و بدون کتابخانه انیمیشن. باید در بیلد آفلاین Capacitor کار کند.
- آدمک یک شکل خیلی ساده: سر دایره‌ای، دو چشم، ابرو، دهان به‌صورت یک `path` که بین ۳ مسیر تعریف‌شده (اخم ملایم / صاف / لبخند) با `transition` مورف می‌شود. بدن اختیاری و مینیمال.
- **حلقه پیشرفت دور آدمک**: یک `circle` با `stroke-dasharray` که `completion` را نشان می‌دهد. آدمک داخل حلقه می‌نشیند. این باعث می‌شود «چهره» و «عدد» یک شیء واحد باشند.
- دو سایز: `sm` (۴۰px، برای `AppTopBar`) و `lg` (۹۶–۱۲۰px، برای Home).
- انیمیشن‌ها فقط CSS transition و keyframe سبک. حتماً `@media (prefers-reduced-motion: reduce)` را احترام بگذار.
- `aria-label` متنی وضعیت را بدهد (مثلاً «آدمک: خوشحال، ۶ ساعت از ۶ ساعت»).
- رنگ‌ها از توکن‌های `brand` در `tailwind.config.ts`. برای حالت‌های پایین از خاکستری/کهربایی استفاده کن، **هرگز قرمز**.

## فاز ۳ — واکنش لحظه‌ای (مهم‌ترین بخش حلقه)

این چیزی است که ثبت داده را اعتیادآور می‌کند: **فاصله بین «ثبت» و «پاداش دیدنی» باید کمتر از یک ثانیه باشد.**

بعد از هر ثبت موفق در `CaptureFormModal` / `GlobalCaptureFab`:

1. آدمک یک انیمیشن کوتاه bounce/pop بزند (۴۰۰ms).
2. حباب گفتار برای ۳ ثانیه دلتا را نشان بدهد — با عدد واقعی:
   - کار مفید: «+۱ ساعت و ۳۰ دقیقه. ۲ ساعت تا هدف.»
   - دارایی مجازی: «+۳۵۰,۰۰۰ تومان به سرمایه پنهانت» (از `/api/virtual-assets/latest-effect` که از قبل هست)
   - هزینه: «۲۴۰,۰۰۰ تومان ثبت شد. حالا دیده می‌شود.» ← حتی هزینه هم به‌عنوان «برد شفافیت» جشن گرفته می‌شود
   - اتلاف: «ثبت شد. حساب امروزت کامل‌تر شد.» ← بدون هیچ سرزنشی
3. اگر این ثبت باعث **عبور از هدف روز** شد: انتقال به `CELEBRATING` با کانفتی، یک بار.

از `UpgradeToast.tsx` موجود به‌عنوان الگوی toast استفاده کن؛ چیز موازی نساز.

## تست‌ها (اجباری)

`src/lib/companion.test.ts` با Vitest، همه با زمان تزریق‌شده و قطعی:

1. `now` قبل از `wakeTime` → `ASLEEP`
2. ۳۰ دقیقه بعد از بیدارشدن با ۰ دقیقه کار → `FRESH` (نه `SLEEPY`) ← **این تست از رگرسیون احساس‌گناه صبحگاهی جلوگیری می‌کند**
3. ظهر، ۳۰ دقیقه کار از هدف ۳۶۰ → `SLEEPY` + پیام دارای اکشن
4. ظهر، دقیقاً روی خط انتظار → `CONTENT`
5. رسیدن به ۳۶۰ دقیقه → `HAPPY` و `completion === 1`
6. ۵۴۰ دقیقه → `CELEBRATING`
7. ۴ ساعت گذشته با ۳ ساعت ثبت‌نشده → `BLINDFOLDED` و اولویتش بالاتر از `SLEEPY`
8. `capacity === 0` (تنظیمات خراب، sleepHour <= wakeHour) → کرش نکند، `ASLEEP` برگرداند
9. `habitMinutes` واقعاً در `achieved` شمرده شود
10. هیچ مودی `message` خالی برنگرداند

`npm test` باید کامل سبز باشد (۵۱ تست موجود + تست‌های جدید).

## نقشه راه — فازهای بعدی (الان پیاده نکن)

**P1**
- **استریک ثبت**: روزهایی که حداقل یک ثبت داشتی. هدف هفتگی ۵ از ۷ (نه کمال‌گرایی روزانه)، ۲ «مرخصی» در ماه، امکان جبران تا ۴۸ ساعت، و نگه‌داشتن «بهترین رکورد» بعد از شکستن.
- **آیین شب (بازسازی روز)**: عصر، آدمک بازه‌های خالی روز را می‌آورد و برای هرکدام ۳ گزینه حدس‌زده از تاریخچه پیشنهاد می‌دهد → یک تپ. بیشترین تولید داده به ازای کمترین اصطکاک.
- **نوار هفته آدمک**: ۷ چهره کوچک برای ۷ روز گذشته — تصویر یک نگاه از هفته.
- **کارنامه هفتگی**: کارت قابل‌اشتراک با چهره هفته + زمان، پول، دارایی ساخته‌شده. حلقه رشد هم هست.
- **قفل داده‌محور گزارش‌ها**: «این گزارش با کمتر از ۱۰ روز داده گمراه‌کننده است — ۶/۱۰» با نوار پیشرفت. صادقانه است، چون واقعاً درست است.

**P2**
- **مأموریت‌ها به‌جای مدال**: «چالش ۷ روز شفافیت»، «شکار هزینه پنهان»، «۱۰۰ ساعت روی یک مهارت». هر مأموریت باید یک پرده آخر داشته باشد: عددی که قبلش نمی‌دانستی.
- **رشد آدمک**: ظاهر آدمک با عبور از milestoneهای سرمایه (`src/lib/milestones.ts`) ارتقا پیدا کند — نه با امتیاز، با دارایی واقعی.
